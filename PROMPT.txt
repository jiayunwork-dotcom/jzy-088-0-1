做一个水平轴风力机叶素动量（BEM）分析的后端服务。一副风轮的叶片沿半径被切成若干叶素，每个叶素有径向位置、弦长和扭角，配一张随攻角变化的升力系数和阻力系数表；给定叶尖速比后，服务对每个叶素迭代求出轴向与切向诱导因子，进而给出当地攻角、微元推力、微元扭矩，并积分出整个风轮的功率系数与推力系数。它做的是叶素动量气动内核，不是风场的发电量看板，也不是单独一条翼型极曲线的展示。

每个叶素的迭代这样进行：由当前诱导因子算出入流角（正切等于一减轴向诱导，比上一加切向诱导再乘当地叶尖速比），攻角为入流角减去扭角，据攻角查翼型表插值得到升阻系数，再更新轴向与切向诱导因子进入下一轮，直到收敛。这些输入要判为非法并给出可读错误：叶尖速比不为正、径向站点少于三个、翼型系数表为空、径向坐标不是单调排列、叶片数不为正整数。梢部要计入普朗特叶尖损失修正；当轴向诱导偏大进入湍流尾流区时，改用一种经过修正的推力关系，而不是继续套用小诱导下的公式让分母失稳。迭代不收敛时报错，不要返回一个看似有值实则发散的结果。

正确性靠若干气动规律锁定，写进测试并带容差：收敛后叶中区域的轴向诱导因子通常落在零到二分之一之间；风轮功率系数不得超过贝兹极限（十六分之二十七）且为正；把叶尖速比从偏低处逐步抬向设计点，功率系数应先上升再趋于平台而非单调乱跳；关掉叶尖损失修正后，梢部微元推力应高于计入损失时；在其它参数不变的前提下把叶片数减少，功率系数应明显下降。请随服务内置一副三叶片风轮的算例，其功率系数为正且低于贝兹极限，可供手工核对。翼型表可以作为一份具名的气动数据登记进服务，供多次分析引用，但这只是数据组织方式，服务的核心仍是那套诱导因子迭代。

服务通过 HTTP 提供两个能力：一是给定单个叶素与叶尖速比，返回该处的轴向、切向诱导因子和整机功率、推力系数；二是给定整片叶片的叶素序列，返回各半径处的攻角、微元推力与微元扭矩。非法输入返回带机器码和说明的错误响应。不需要任何前端页面，也不涉及登录。请把入流角与攻角求解、翼型表插值、诱导因子迭代与尾流修正、叶尖损失、沿叶片的积分、翼型数据登记与管理、输入校验、HTTP 层拆分为彼此独立的模块与文件，不要把迭代内核和积分逻辑压在一个大类里。

用 Java 17 配合 Spring Boot 实现。请提供把服务打包成镜像、单条命令启动并对外提供接口的容器化配置，并附自动化测试，覆盖非法输入、功率系数不超过贝兹极限、叶尖速比扫描下功率系数先升后平、去掉叶尖损失使梢部载荷升高、减少叶片数使功率系数下降。
